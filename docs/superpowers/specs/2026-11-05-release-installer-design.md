# Release 遠端安裝設計（已核准）

目標：讓 AI agent 在已準備備份服務的 PVE 主機，以指定版本的 GitHub Release 安裝報告程式及 systemd 掛鉤。安裝器不建立備份服務、排程、PBS 儲存或 Discord Webhook。

## 方案

- 建議：發布固定版本的安裝腳本、程式與 drop-in，提供 SHA-256 校驗資訊。先下載腳本、檢查來源及校驗值，再執行。可重現指定版本，但校驗資訊若與檔案同源，不能單獨證明發行者身分。
- 替代：直接從主分支下載並執行。命令較短，但內容可能隨時改變，回溯與重現困難。

## 安裝契約

1. 在寫入前檢查 root、PVE 版本、依賴、兩個已存在的服務和報告程式自我測試；條件不符則失敗退出，說明缺少項目。
2. 下載指定 Release 資產，校驗後保存原檔及原本不存在的狀態；覆蓋程式與兩個 drop-in，重新載入 systemd 並驗證生效。
3. 發生錯誤時回復已變動檔案；提供明確可執行的手動回復方式。不得輸出或保存 Webhook 機密至倉庫、終端歷史或日誌。
4. 不啟動備份或發送通知；管理員另行執行測試，確認 Discord 送達。安裝成功不代表備份成功或可還原。
5. 乾淨測試 VM 上分別驗證缺少服務時無寫入、已設定測試服務時安裝、更新回復和成功／失敗通知；不得操作正式備份資料。

## 待決與驗證

已實作安裝腳本並在測試 VM 驗證模擬通知；Release 的公開下載需在發行後驗證。完整從零建置備份服務及其測試方式仍須另行設計；現有自訂服務與 PBS 設定不在倉庫內。
