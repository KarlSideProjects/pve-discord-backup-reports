# 結構化 Discord 備份報告

使用者選擇方案 B：將備份報告改為可在手機閱讀的 Discord Embed，包含主機、狀態、時間及各 VM／CT 的獨立欄位。

方案 A 只將既有文字包成 Embed，改動少但不具逐項結構。方案 B 在報告程式產生結構化資料，經 PVE Notifications 傳遞至 Webhook；保留既有路由與 PVE 管理的密鑰，不另建 Bot。PVE metadata 對應和模板分支須在測試 VM 證實可用後才部署。

成功、失敗與資料缺漏分別呈現，PBS 離線維持略過且不通知。資料不完整不可標為完全成功；結束時間須註明是報告時間。限制 Discord 訊息大小，保留失敗資訊並明示省略，禁止 mentions；發送失敗保留日誌但不得改變備份結果。須避免其他 PVE 通知中斷或重複。不得儲存 webhook 密鑰到程式或倉庫。

測試缺少記錄、長名稱及訊息、錯誤、特殊字元、離線、成功，並在測試 VM 實際發送；手機排版仍需實機確認。備份本身與還原不在測試範圍。
